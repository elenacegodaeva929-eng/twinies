# Twinies — сайт студии

Статический сайт: HTML, CSS, картинки. Никаких сборок.
Можно открыть `index.html` двойным кликом и посмотреть локально.

**Все файлы лежат в корне репозитория, папок нет.** Картинки тоже —
так загрузка работает в любом браузере и ничего не теряется.

---

## Что где лежит

| Файл | Что внутри | Кому трогать |
|---|---|---|
| **content.js** | Фаундеры, подразделения, сотрудники, фильмы, лента работ, контакты | **Главный файл для правок.** Клиент может сам |
| **index.html** | Каркас + заголовок вкладки и описание для поисковиков | Правится текст в отмеченных местах |
| styles.css | Цвета, шрифты, сетки, анимации | Только через дизайнера |
| app.js | Раскрытие карточек, окна, формы | Не трогать |
| *.png | Логотипы, сигилы подразделений, фото, афиши | Складывать рядом с остальными файлами |

## Как обновить сайт

### Поправить текст

1. Открыть репозиторий → кликнуть на `content.js`
2. Карандаш справа сверху → изменить
3. Внизу **Commit changes** → ещё раз **Commit changes**
4. Через 30–60 секунд правка на сайте. Если не видно — обновить страницу
   с `Cmd+Shift+R` (Mac) или `Ctrl+F5` (Windows), браузер кэширует.

### Заменить файл или добавить картинку

**Add file → Upload files** → перетащить файлы в окно браузера → **Commit changes**.
Файлы с теми же именами заменятся, новые добавятся.

Потом в `content.js` вписать имя файла: `photo: "kseniia.jpg"`

### Если сломалось

Вкладка **Commits** → найти момент до поломки → кнопка возврата.
История хранится вся, потерять ничего нельзя.

## Как править контент (инструкция для клиента)

Открыть **content.js**. Внутри всё подписано по-русски. Три правила:

1. Текст всегда внутри кавычек: `name: "Kseniia Klever"`
2. После строки — запятая, кроме последней в блоке.
3. Внутри текста двойные кавычки `"` не ставить — вместо них «ёлочки».

Чтобы **добавить сотрудника** — скопировать строку `{ name: … }` целиком,
вставить ниже и переписать. Чтобы убрать — удалить её вместе со скобками.

Для **трейлера** нужна ссылка в особом виде, обычная из адресной строки
не подойдёт:

- YouTube — `https://www.youtube.com/embed/КОД_ВИДЕО`
- Vimeo — `https://player.vimeo.com/video/НОМЕР`

## Формы

Статический сайт сам письма не отправляет. Сейчас обе формы собирают ответы
и открывают почтовую программу с готовым письмом.

Когда появятся гугл-формы — впишите ссылки в `content.js`
(`createForm` и `joinForm`), и кнопки поведут туда.

## Портфолио: куда класть материалы

Правило простое: **в репозитории — только превью, тяжёлое — на диске.**

### Полное портфолио → Google Drive / Яндекс.Диск

Папка с доступом «по ссылке», ссылка вписывается в `content.js`:

```js
portfolio: "https://drive.google.com/drive/folders/...",
```

В карточке человека появится кнопка **Open full portfolio →**.
Так уже сделано у восьми ребят. Диск не ограничен по объёму, видео
туда тоже можно — а репозиторий остаётся лёгким.

### Превью → в репозиторий, 3–6 картинок на человека

```js
projects: ["pf-katya-01.jpg", "pf-katya-02.jpg", "pf-katya-03.jpg"],
```

Они откроются сеткой в окне «Projects», там же будет кнопка на полное портфолио.

**Как называть.** Папки не нужны — имя файла само работает как папка:
`pf-katya-01.jpg`, `pf-ilya-01.jpg`, `film-poster.jpg`. Всё лежит в корне,
загружается перетаскиванием в любом браузере, ничего не ломается.

Если очень хочется настоящую папку: **Add file → Create new file**, в поле
имени набрать `pf/katya/.keep` — GitHub создаст папку. Но тогда в `content.js`
путь пишется целиком: `"pf/katya/01.jpg"`. Лишний шанс ошибиться, поэтому
рекомендую имена с префиксом.

### Размер файлов

| | |
|---|---|
| Превью работы | ширина 1400–1600 px, JPEG, 200–400 КБ |
| Фото человека | 800×800 px, JPEG, до 200 КБ |
| Афиша фильма | 1200×1700 px, JPEG, до 500 КБ |
| Видео | **в репозиторий не класть** — YouTube/Vimeo или диск |

Лимиты GitHub Pages: репозиторий до 1 ГБ, опубликованный сайт до 1 ГБ,
трафик 100 ГБ в месяц. На превью этого хватит с большим запасом — 200 картинок
по 300 КБ это всего 60 МБ. Упираемся мы не в лимит, а в скорость: каждый
лишний мегабайт на главной — это секунда загрузки у посетителя. Поэтому
картинки перед загрузкой лучше сжимать (squoosh.app, tinyjpg.com — бесплатно,
прямо в браузере).
