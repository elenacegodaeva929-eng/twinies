# Twinies — сайт студии

Обычный статический сайт: HTML, CSS, картинки. Никаких сборок и установок,
файлы работают как есть. Можно открыть `index.html` двойным кликом и посмотреть
локально, можно залить на любой хостинг.

---

## Что где лежит

| Файл | Что внутри | Кому трогать |
|---|---|---|
| **content.js** | Владельцы, подразделения, сотрудники, проекты, почта | **Это главный файл для правок.** Клиент может сам |
| **index.html** | Каркас страницы + текст главного экрана и заголовок вкладки | Правится текст в отмеченных местах |
| styles.css | Цвета, шрифты, сетки, анимации | Только через дизайнера |
| app.js | Раскрытие карточек, окно проекта, формы | Не трогать |
| img/ | Картинки: лого подразделений, фото, обложки | Складывать сюда новые |

## Как выложить на GitHub Pages

**Один раз:**

1. Завести аккаунт на github.com.
2. Кнопка **New repository**. Имя — например `twinies`. Выбрать **Public**
   (на бесплатном тарифе Pages работает только из публичных репозиториев).
   Нажать **Create repository**.
3. На странице репозитория — ссылка **uploading an existing file**.
   Перетащить туда все файлы и папку `img` целиком. Внизу — **Commit changes**.
4. **Settings → Pages**. В разделе *Source* выбрать **Deploy from a branch**,
   ветка `main`, папка `/ (root)`. **Save**.
5. Через минуту-две сайт живой по адресу
   `https://ВАШ-ЛОГИН.github.io/twinies/`

> Хотите адрес без хвоста — назовите репозиторий `ВАШ-ЛОГИН.github.io`,
> тогда сайт будет на `https://ВАШ-ЛОГИН.github.io/`

**Свой домен:** купить у любого регистратора, затем Settings → Pages →
*Custom domain* вписать его и у регистратора прописать записи, которые
GitHub там же покажет. Сертификат HTTPS выпустится сам, обычно за час.

## Как обновлять сайт

**Поправить текст:** открыть файл в репозитории → карандаш справа сверху →
изменить → внизу **Commit changes**. Через полминуты изменения на сайте.

**Заменить файл целиком:** **Add file → Upload files** → перетащить новый
файл с тем же именем → Commit. Старый заменится.

**Откатиться:** вкладка **Commits** → найти нужный момент → кнопка возврата.
История хранится вся, потерять ничего нельзя.

## Как править контент (инструкция для клиента)

Открыть **content.js**. Внутри всё подписано по-русски. Три правила:

1. Текст всегда внутри кавычек: `name: "Ksenia Klever"`
2. После строки — запятая, кроме последней в блоке.
3. Внутри текста двойные кавычки `"` не ставить — вместо них «ёлочки».

Чтобы **добавить сотрудника** — скопировать строку `{ name: … }` целиком,
вставить ниже и переписать. Чтобы убрать — удалить её вместе с фигурными
скобками и запятой.

Чтобы **добавить фото** — положить файл в папку `img/` и вписать путь:
`photo: "img/ksenia.jpg"`.

Для **шоурила** нужна ссылка в особом виде, обычная из адресной строки
не подойдёт:

- YouTube — `https://www.youtube.com/embed/КОД_ВИДЕО`
- Vimeo — `https://player.vimeo.com/video/НОМЕР`

Если после правки сайт сломался — значит потерялась кавычка или запятая.
Откатитесь через вкладку Commits и попробуйте снова.

## Формы

Статический сайт сам письма не отправляет. Сейчас настроено так:

- **Create art** — если в `content.js` вписать ссылку в `createForm`,
  кнопка поведёт на вашу гугл-форму. Пока пусто — показывается форма-заглушка,
  которая никуда не отправляет.
- **Become a twinie** — собирает ответы и открывает почтовую программу
  с готовым письмом на адрес из поля `email`.

Если нужен нормальный приём заявок прямо на сайте, без гугл-формы —
подключается сервис вроде Formspree или Getform, это отдельный шаг.

## Что ещё не доделано

- Лого студии и картинка клоуна на главном экране — поля `heroLogo` и
  `heroClown` в `content.js`. Пока там пунктирные рамки.
- Фото владельцев и сотрудников.
- Реальные проекты вместо трёх заглушек.
- Картинка для превью в соцсетях — положить в `img/`, прописать `og:image`
  в `index.html` (место отмечено комментарием).
